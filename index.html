Projects

Sales ETL — PySpark + Airflow

data engineering

Cleans a deliberately messy sales dataset (4 date formats, inconsistent country and payment names, "$" prices, duplicates, invalid quantities, nulls) and delivers it ready for analysis.

Sales CSV→ PySpark cleaning→ Quality gate→ Parquet by country+ PostgreSQL
  • Conflicting duplicates are resolved with window functions: the latest version of each order wins.
  • A quality gate aborts the run if more than 50% of rows are discarded, so a bad file never overwrites good data.
  • Airflow DAG with 3 tasks, automatic retries and email alerts on failure. Idempotent runs, covered by pytest.
PySpark Airflow PostgreSQL Parquet pytest Docker

Orders pipeline — Airflow, star schema, dbt on BigQuery

data engineering

Order data from 3 regional stores, built in two repos: an Airflow ETL that handles failures, and an ELT layer where dbt models the data as a star schema in BigQuery.

pedidos-etl-airflow
Store orders→ Airflow ETL→ PostgreSQL→ Star schema
pedidos-dbt-bigquery
BigQuery raw→ dbt models→ Fact + 3 dimensions→ Data tests
  • The ETL handles 5 types of production failures (damaged files, duplicates, dropped connections) and ships with automated tests.
  • The star schema has 1 fact table and 3 dimensions, built as 4 dbt models linked with ref().
  • dbt tests check keys and relationships. Access to BigQuery uses service-account impersonation, with no downloaded JSON keys.
